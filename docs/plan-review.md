# 従来の卒論計画の妥当性レビュー

評価日：2026-10-08  
対象：[旧研究計画](research-plan.md)の初期整理版（テーマ→資料棚卸し→使える／使えない→文献レビュー→不足の抽出→調査設計→執筆）。このレビューは**計画の論理性の評価**であり、研究テーマに即した実証可能性の承認ではありません。

## 結論

**骨格は妥当だが、順序と判断基準が粗いため、修正して運用する。** 特に①テーマ確定の前後で文献探索を往復する、②「使える」と「信頼できる」を別軸で判断する、③独自調査の実施可能性を早めにテストする、④出典・倫理・執筆のトレーサビリティを設ける、の4点が必要。

| 旧案 | 評価 | 修正・理由 |
|---|---|---|
| テーマ・問いを最初に完全確定 | 要修正 | まず**仮RQ**を置き、スコーピングレビューで改訂。先行研究を知らずに固定すると問いが広すぎる／既出の可能性がある |
| iCloud文献を全件一覧化 | 継続 | ファイル名・重複・出典・本文可読性・一次／二次情報を先に識別 |
| 「使える／使えない／保留」に分類 | 条件付き継続 | 二値だけにせず保留を使う。**研究への適合度、根拠の信頼性、利用目的を別々に評価**。テーマ変更時は再判定 |
| 過去の優秀卒論を分析 | 継続（用途限定） | 問いと方法・論理構成の参考にはなるが、その分野の先行研究そのものの代替にはならない。研究手法を模倣するだけでは不十分 |
| 文献レビューでギャップを探す | 強化 | 要約集ではなく**論点別の比較と不一致の検討**。ギャップは「誰もやっていない」だけでなく、理論上／政策上の重要性も説明 |
| 不足を見つけてから調査設計 | 要修正 | 研究課題を絞る段階で**データ入手性・標本・時間・倫理・分析能力**を同時に評価 |
| 調査→分析→執筆 | 要修正 | 方法の妥当性確認と小規模パイロット、指導教員からのフィードバックを追加。執筆は研究背景や方法案から並行着手できる |
| 期限は後で考える | 要修正 | 公式の提出日・途中提出日を確認して逆算。日付を勝手に決めず、相対マイルストーンで管理 |

## 研究設計で特に注意すべきこと

- **研究問い（RQ）と手法の対応**：説明・意味理解を目指すなら質的研究、現状推定や関連を問うなら適切な調査・統計、因果効果なら交絡や識別戦略を考える。「優秀論文がアンケートだったから」では手法を選ばない。
- **標本と到達可能性**：対象母集団、リクルート経路、予想回収数、欠測・偏りを明記。必要な分析に対するデータ量の見通しを持つ。
- **実行可能性のゲート**：予定したデータを取得できない場合の代替RQ・手法を用意。未取得データの分析結果を想定で書かない。
- **研究倫理**：個人への調査前に同意、匿名化、保存場所、学校の倫理手続きの要否を確認。公開GitHubに個票を置かない。
- **出典の検証**：本文にない主張、未確認のページ・DOI、直接読んでいない原典を「読んだ」とする二次引用を禁止。

## 改訂後の進め方

1. ゼミ条件・既存テーマ案の復元と暫定RQ設定
2. 文献の棚卸し＋主要文献の予備読み（反復）
3. 論点別レビューと問いの絞り込み
4. 調査可能性のテストと方法案比較、指導教員レビュー
5. パイロット→本調査・分析（必要な承認後）
6. 先行研究・分析・考察を整合させ執筆、検証して提出

各段階の完成条件は [研究計画](research-plan.md)。方法を決める具体的判断基準は [調査設計](research-design.md)。

## この時点では判定できないこと

研究テーマ・対象地域・研究対象者・卒論要件・資料本文が未確認のため、**個別RQの新規性、学術的貢献、アンケート／統計手法の適切さ、実際のスケジュールの達成可能性**は評価保留です。確定後に本レビューを改訂します。
